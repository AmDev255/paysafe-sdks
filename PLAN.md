## 1. Facts established 2026-11-01 (do not re-derive)

- API base: `https://api.paysafe.co.tz`, path prefix `/v1`, environment chosen by key prefix (`paysafe_test_` sandbox, `paysafe_live_` production). Auth: `Authorization: Bearer <secret key>`. No other auth.
- 29 served operations in 10 tags (full list in `coverage-matrix.md`). Reviewed `openapi.yaml` is behind the generated file: it lacks Payment links, Control numbers and Transfers. Documentation gap to report, not to fix in this program.
- Request headers: `Idempotency-Key` required on `POST /v1/payments`, `POST /v1/refunds`, `POST /v1/transfers` (generated spec marks it required), optional on `POST /v1/payments/{id}/cancel`, not accepted elsewhere. `X-Request-ID` optional (8–64 chars `A–Z a–z 0–9 . _ -`). `PaySafe-Version` optional date version. Body limit 64 KB, `Content-Type: application/json`.
- Response headers: `X-Request-ID` always; `X-RateLimit-Limit/Remaining/Reset` on authenticated requests; `Retry-After` on 429/503; `Idempotent-Replayed: true` on replays; `Deprecation`/`Sunset`/`Link` for deprecations.
- Error envelope: `{ "error": { code, message, request_id, param?, details?, doc_url? } }`. Codes → status: validation_error 400, authentication_error 401, permission_error 403 (details.code ip_not_allowed / ip_allowlist_empty, details.ip), feature_disabled 403, not_found 404, insufficient_funds 402, conflict 409, idempotency_conflict 409, idempotency_in_progress 409, invalid_state 409, rate_limited 429 (details.scope), provider_error 502, provider_unavailable 503, service_unavailable 503, plus internal 500. Unknown code → branch on status.
- Retry policy (from docs): 409 idempotency_in_progress → sleep 1 s, retry same key; 429/503 → wait `Retry-After`, retry same key; 5xx/network → backoff, retry same key; other 4xx → stop. Max 5 attempts. Keys expire after 24 h. Never auto-generate a fresh key on retry.
- Pagination: `{ object: "list", data, has_more, next_cursor }`, `limit` 1–100 default 25, `cursor` query param.
- Money endpoints return `202 Accepted` (createPayment, createRefund); createPaymentLink/createControlNumber/createTransfer/createWebhookEndpoint return 201; deleteWebhookEndpoint 204. 202 is not success; poll or use webhooks.
- Payment statuses: created, pending, processing, requires_action, succeeded, failed, cancelled, expired, partially_refunded, refunded. Terminal: succeeded, failed, cancelled, expired (refunded/partially_refunded are post-success). Refund: pending, processing, succeeded, failed, rejected. Transfer: completed, in_review, rejected, reversed. PaymentLink: active, paused, archived. ControlNumber: active, paid, expired, cancelled.
- Event types (22): payment.pending/processing/requires_action/succeeded/failed/expired/cancelled, refund.pending/succeeded/failed, payout.processing/paid/failed, transfer.sent/received/in_review/rejected/reversed, control_number.partially_paid/paid/expired/cancelled.
- Webhook signature: header `PaySafe-Signature: t=<unix>,v1=<hex>` (several `v1=` during rotation, 24 h), HMAC-SHA256 over `${t}.${rawBody}`, tolerance 300 s, constant-time compare. Other headers: `PaySafe-Event-Id`, `PaySafe-Delivery-Id` (whd_), `PaySafe-Attempt`, `User-Agent: PaySafe-Webhooks/1.0`. Reference implementation `paysafe/packages/core/src/infra/security/index.ts` (`signWebhook`, `verifyWebhookSignature`). Test vector: secret is `{{key.webhookSecret}}test_2f4c9b7e1a3d5f6c8e0b2a4d6f8c1e3b` (resolve the brand placeholder from `packages/brand`), timestamp `1788775204`, signature `880ac7fb8a4bb2ddbd615706ebabde6dbd040552d546b830c5a696e7b23b3d08`, body is the worked example in `docs/api/content/webhooks.md`.

- Scopes: payments:read/write, refunds:read/write, balance:read, customers:read, customers:read_pii, webhooks:read/write, events:read, `*`.
- Ids are prefixed ULIDs: pay_, rfd_, pyo_, cus_, whe_, evt_, whd_, lex_, req_. Amounts integer TZS. Phones E.164 `+255` + 9 digits. Timestamps RFC 3339 UTC.
- Existing examples: `paysafe/docs/api/examples/<lang>/{auth,create-payment,get-payment,verify-webhook}.*` for all 10 languages, checked by `node docs/api/examples/check.mjs`. JS/TS/Python examples run in CI against a local server (`tests/docs-examples.spec.ts`).

## 3. Shared contract (stage S2 deliverables, kept in `contract/`)

- `contract/openapi.json`: byte copy of `paysafe/docs/api/openapi.generated.json` with its version recorded in `contract/VERSION`.
- `contract/endpoints.md`: operationId, method, path, auth scope, headers, params, body schema name, success status, error codes, idempotency, pagination.
- `contract/errors.md`: the error model every SDK exposes (one base exception + one subclass per code, plus `ApiConnectionError`, `ApiTimeoutError`, `SignatureVerificationError`). Fields: status, code, message, requestId, param, details, docUrl, headers, retryAfter.
- `contract/retry.md`: the retry loop above, defaults max 5 attempts, base backoff 500 ms, cap 8 s, jitter, honour Retry-After, never retry non-idempotent requests without a key, never regenerate keys.
- `contract/polling.md`: `waitForPayment(id, {interval=2s, timeout=120s, cancel})`, `waitForRefund`, terminal states per resource.
- `contract/webhooks.md`: verification algorithm, headers, rotation (multiple v1), replay/duplicate guidance, test vector.
- `contract/fixtures/`: JSON request/response fixtures per operation (success + each documented error) generated from spec examples; `fixtures/webhook-vector.json` (secret, timestamp, body, signature); `fixtures/retry-scenarios.json`. Every SDK's contract tests load these same files (copied into each repo under `tests/fixtures/`, kept in sync by `tools/sync-fixtures.mjs`).
- `contract/sdk-surface.md`: the resource/method naming table (section 4) so all ten expose the same operations.

## 4. Standard SDK surface (same in every language, native casing)

Client construction: `apiKey` (required), `baseUrl` (default `https://api.paysafe.co.tz`), `timeout` (default 30 s), `maxRetries` (default 5), `apiVersion` (optional `PaySafe-Version`), `httpClient` (injectable), `logger` (optional). ## 9. Session resume protocol

1. Read `STATUS.md`. The first unchecked box is the current task. Read the notes under that stage for context left by the previous session.
2. Re-read `PLAN.md` section 0 (rules) and section 1 (facts). Do not re-audit the API unless `contract/VERSION` differs from `info.version` in `paysafe/docs/api/openapi.generated.json`.
3. Tokens: ask the user for the GitHub token if `gh-token.txt` is not in the current session scratchpad. Never read tokens from the repo folders.
4. Before pushing anything: run that repo's gate, run the secret scan, check the remote repo state with the API.
5. After finishing any stage: update `STATUS.md` and `coverage-matrix.md`; update the memory file `paysafe-sdk-program.md` only if a rule or decision changed.
